# Feature plans

Proposals and **approved roadmap** docs for work that is **not yet** a `PHASE_*.md` execution plan.

**Where new ideas go:** [GitHub Issues](https://github.com/) (and milestones). Use this folder when an idea needs a shaped plan (options, non-goals, open questions) before build.

**Lifecycle**

1. Draft here (`docs/feature_plans/<slug>.md`) when the issue needs more than a ticket
2. Resolve open questions with the owner
3. Promote to a phase doc, fold into existing work, or park
4. When the slice **ships**, move the file to [shipped_features/](../shipped_features/README.md) (or leave a short “Shipped in place” note here)

**Status vocabulary**

| Status | Meaning |
| ------ | ------- |
| **Proposal** | Shaped idea; not committed roadmap |
| **Roadmap** | Owner intends to build; not scheduled yet |
| **Curiosity / far-field** | Captured for later; shape may change |
| **Far-future (v2+)** | Explicitly after first real show/season |
| **Parked / declined** | Not pursuing (say why) |
| **Shipped** | Belongs in [shipped_features/](../shipped_features/README.md) |

Authoritative product/schema docs win on conflict: [PROJECT.md](../PROJECT.md), [DATABASE.md](../DATABASE.md), active phase docs.
