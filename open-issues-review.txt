#82  [enhancement]  Migrate bookmarks to use the new act/scene/moment link system
https://github.com/connorsharpmckinnis/production_app/issues/82
----------------------------------------
## Summary

Timeline deep links are moving to human show-position params:

- `/productions/:id/timeline?act=1&scene=2` ΓåÆ scene start (first moment for now)
- `/productions/:id/timeline?act=1&scene=2&moment=115` ΓåÆ that moment within the scene

Old PK-based links (`?scene=<sceneId>&moment=<momentId>`) remain supported for compatibility.

Bookmarks still store `moment_id` (PK) and emit PK-based URLs. Migrate them to the same improved link shape so share/CTA/bookmark navigation feels consistent.

## Current behavior

- `bookmarks` table: `user_id` + `moment_id` (+ optional label)
- Sidebar / menu links: `/productions/{production_id}/timeline?scene={scene_id}&moment={moment_id}`
- Storage by PK is fine for ΓÇ£this exact momentΓÇ¥; the **emitted URL** is what should align with the new contract

## Proposal

1. Keep storing `moment_id` as the bookmark identity (stable under soft position drift for the userΓÇÖs own pin).
2. When rendering bookmark hrefs, resolve the momentΓÇÖs current `act.number`, `scene.number`, and `sequence_number` and link as:
   `/productions/{id}/timeline?act={n}&scene={n}&moment={seq}`
3. Optionally accept/paste human links when creating bookmarks later (picker / ΓÇ£copy linkΓÇ¥ on Moment Detail).
4. Leave PK URL consume path until a later cleanup pass removes it.

## Why not change storage yet

Soft links mean `act/scene/moment` numbers can drift after structural edits. Bookmarks are personal pins to a specific moment row ΓÇö PK storage remains the right durable identity. The enhancement is mainly **URL shape / UX consistency**, not replacing the FK.

## Acceptance criteria (rough)

- [ ] Bookmark click opens Timeline via `act`/`scene`/`moment` query params
- [ ] Still works after moment sequence renumber (bookmark follows the row via `moment_id`)
- [ ] Copy-link / share from Moment Detail uses the same human URL shape
- [ ] Old PK bookmark links (if any were shared externally) still resolve until explicitly deprecated

## Related

- Human Timeline deep-link work (announcement CTAs / Timeline consume)
- Future: destination picker for announcement CTAs
- Future: pre-scene overview chip as scene-start target when `moment` is omitted

#81  [enhancement]  CTA enhancement picker system to generate the link to teh exact moment desired
https://github.com/connorsharpmckinnis/production_app/issues/81
----------------------------------------
## Summary

Announcement CTAs currently require authors to type an internal app path by hand (e.g. `/productions/18/timeline?scene=45&moment=891`). That works, but itΓÇÖs hard to discover and easy to get wrong ΓÇö especially for deep links to a specific Timeline moment.

## Problem

- Authors must know route conventions and numeric production / scene / moment IDs.
- Moment IDs arenΓÇÖt surfaced in the composer UI; you have to scrape them from bookmarks, reports, or the API.
- Easy to use invalid paths (e.g. `/productions/18/overview`, which isnΓÇÖt a real route) or miss query params.

## Proposal

Add a destination picker in the announcement composer (org-wide and production-scoped) that lets the author choose a target without memorizing URLs, for example:

1. **Page** ΓÇö Overview, Timeline, Rehearse, Characters, Props, Costumes, Reports, Settings, etc.
2. **Timeline scene** (optional) ΓÇö when Timeline is selected.
3. **Moment** (optional) ΓÇö searchable/selectable within the chosen scene (or production-wide search).

The picker would write the correct internal path into the CTA target (same allowlisted format we already validate), e.g.:

- `/productions/18`
- `/productions/18/timeline`
- `/productions/18/timeline?scene=45&moment=891`

## Out of scope (for now)

- Rehearse moment deep-links (not supported yet)
- Line-number / dialogue-text deep-links
- External URL picker beyond a normal URL field

## Acceptance criteria (rough)

- [ ] Composer offers browse/select instead of (or in addition to) free-text internal path
- [ ] Production announcements default the production id from context
- [ ] Org-wide announcements prompt for production when a show-scoped page is chosen
- [ ] Selected moment CTAs open Timeline Moment Detail via existing `?scene=&moment=` deep-link
- [ ] Free-text path remains available as an advanced escape hatch
